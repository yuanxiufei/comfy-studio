# 智能体搭建参考md/ —— **对外迁移配置**（不是本仓库的权威规则）

> 本目录收录 6 份「**完整迁移配置**」。它们的用途是**把智能体迁移到其他平台** ——
> 每份规格都自己写明了这一点，例如最近更新的那份：
>
> > 用途：将本智能体**迁移到其他 GPT / Agent / 工作流平台**时，作为完整的行为规范、
> > 输出规范与提示词生成规范。
> > 建议：将本文档主体内容复制到**目标智能体**的 System Prompt / Instructions 中……
>
> 且它们都**自包含**：不依赖本仓库的任何代码，复制走就能用。

---

## 一、⭐ 与工作流的分工（**别把这两个当成"两个权威"**）

| | **本目录** | `AI漫剧智能体工作流/` |
|---|---|---|
| 定位 | **对外迁移配置** | **本仓库的权威规则 + 可执行实现** |
| 形态 | 自包含 prompt / spec，无依赖、无代码 | 规则文档（23+ 份） + `07-智能体运行时` 的 Python |
| 强制力 | 只能**描述**规则（靠模型遵守） | ID 分配 / 版本号 / 一致性 Gate / 锁定指纹 / 参考图链 / 漂移检测**由代码强制** |
| 何时看它 | **要迁出**（在别的平台复刻这个 agent） | **在本仓库干活** |

**所以「哪份权威」这个问题不存在** —— 用途不同：

- **在本仓库内工作** → 以 `AI漫剧智能体工作流/` 为准（那是本仓库的产物规范与代码行为）；
- **要迁到别的平台** → 以本目录的对应规格为准（那是"带走的那一份"）。

⚠️ **两者不自动同步。** 改了工作流 ≠ 本目录跟着变，反之亦然。
「要不要同步」是**人工决定** —— 用途不同，**允许不同步**，
但**不允许在没意识到的情况下不一致**，故把这条写在这里。

> **依据（实测）**：`AI漫剧服化道智能体_完整迁移配置.md` 与工作流 `02-服化道/`
> 互含率 **0.0%** —— 它们本就是两件东西；而**该规格的旧版**与工作流
> `02-服化道/00-主控智能体.md` 曾 **100% 同一份**，所以当时判定"不该再存一份副本"。
> ⚠️ **判据随事实而变** —— 源文件一更新，结论就得重算。

## 二、命名约定

```
<名称>_完整迁移配置.md
```

统一掉了此前三种不一致：分隔符 `｜` vs `_` · 后缀 `完整迁移版` / `完整迁移配置` /
`_Markdown`（后者纯冗余，本来就是 .md）· 名称里夹的描述性长尾。

> ⚠️ **文档内的标题不动**（如 `# Suno 歌词大师｜完整智能体迁移配置`）——
> 那是**内容**，不是文件名。

## 三、目录清单

| 规格 | 对应工作流模块 | 对应 CodeBuddy 子智能体（`..\.codebuddy\agents\`） |
|---|---|---|
| `AI剧本创作_完整迁移配置.md` | 01 剧本文本 | `manju-script-creator`（**自动**） |
| `AI漫剧服化道智能体_完整迁移配置.md` | 02 服化道 | `manju-costume-prop-engine`（手动） |
| `AI漫剧资产库角色道具_完整迁移配置.md` | 02 服化道 | `manju-asset-library`（手动） |

| `Suno歌词大师_完整迁移配置.md` | 05 音乐音频 | `manju-suno-lyric-master`（**自动**） |
| `调音大师班_完整迁移配置.md` | 05 音乐音频 | `manju-audio-tuning-master`（**自动**） |

子智能体由 `.codebuddy/agents/_build.py` **逐字移植**生成（正文 = 本目录对应规格原文）。
**改了本目录的规格 → 重跑一次生成脚本**，否则部署的 agent 仍是旧规则：

```bash
python .codebuddy/agents/_build.py
python AI漫剧智能体工作流/07-智能体运行时/tests/test_agents.py   # 含"生成物 == 重算"检查
```

## 四、新增/更新规格时

1. 命名按 §二 的格式；
2. 若是**新模块**的规格，在 `.codebuddy/agents/_build.py` 的 `SOURCES` 加一行
   （`module` / `mode` 必填 —— 自动入口需与联动型一起对上 `tests/test_agents.py` 的**名册**）；
3. 重跑生成脚本 + 校验测试。
