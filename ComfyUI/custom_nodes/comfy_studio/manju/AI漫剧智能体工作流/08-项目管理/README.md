# 08 项目管理 · 一部小说 → 一部漫剧的「资料放哪儿」唯一约定

> **本模块管「放哪儿」，不管「怎么生成」** —— 生成规则在 01–06 各模块，代码在 `07-智能体运行时/`。
> 本模块是它们的**共用落点约定**，也是**项目侧目录的唯一权威**。

---

## 一、它解决什么问题

**一部小说 = 一个项目目录。** 从原文到成片，每一份中间资料在这个目录里
**有且只有一个该放的位置**。

不这么做的代价不是"乱"，而是**找错文件还不报错**：

| 症状 | 后果 |
|---|---|
| 分镜用的是上一版剧本 | 与已出图对不上，重出 |
| 提示词引用了旧 ID | 画面里出现已废弃的造型，**且看起来正常** |
| 某个角色的资产只在某人脑子里 | 那几集**画不出来**，临到分镜才发现 |
| 原著授权 / 参考素材来源没记 | 版权问题拖到发布前才暴露（BLOCKING 项） |

所以本模块的产物是**一套目录 + 一张流程映射表 + 一组模板**，
并且把它们**接到运行时**（`python main.py project`），让「建项目 / 查缺失」可机械执行。

---

## 二、两层结构：库 / 项目

| 层 | 位置 | 属性 | 放什么 |
|---|---|---|---|
| **库**（本工作流） | `AI漫剧智能体工作流/` | **只读** | 规则 / 模板 / 引擎 / 这套目录规范 |
| **项目** | `projects/<项目名>/` | **可写** | 这一部剧的全部资料与产物 |

> ⚠️ **项目不复制规则**。库一改，所有项目立刻跟上 —— 本仓库第一纪律「同一知识一处维护」。

项目根**动态探测**（不写死机器路径）：环境变量 `VOIDE_PROJECTS_ROOT` 优先，
否则从 `07-智能体运行时/` 往上找含 `projects/` 的那一级。

## 四、怎么用：一键建项目

```bash
cd AI漫剧智能体工作流/07-智能体运行时

python main.py project new 我的剧                 # 按本规范建全套目录 + 入口文件
python main.py project list                       # 有哪些项目
python main.py project check 我的剧               # 体检：缺哪个落点、哪一阶段还没产物
python main.py project new 我的剧 --升级           # 给已有项目补新增落点（不覆盖已有文件）
```

> 命令的**目录清单**直接来自 `src/project.py` 的 `PROJECT_DIRS`，
> 而它必须与 `项目目录规范.md` 一致 —— 两者不一致由 `tests/test_project.py` 机械核对。

## 六、与其他权威的关系（**冲突时以谁为准**）

| 事项 | 权威 |
|---|---|
| 项目目录逐层职责 + 文件命名 + 谁写谁读 | ⭐ **本模块 `项目目录规范.md`** |
| 流水线本身（阶段 / 输入输出 / 门禁） | `生产流程规范（S0-S7）.md` |
| ID 前缀与交接协议 | `00-总控路由.md` §四 |
| 资产卡 / 视觉圣经的**字段级**细节 | `02-服化道/模板/` 与 `02-服化道/项目骨架/README.md` §二 与 §三 |
| 剧本格式硬标准 | `01-剧本文本/模板/剧本与角色小传模板.md` §一 |

本次是把原先**分散在两处**的目录约定（`02-服化道/项目骨架/README.md` §一、
`生产流程规范（S0-S7）.md` §七）**收敛到本模块**，那两处现改为指向这里 ——
避免「同一份目录树三处维护，改一处忘两处」。

## 七、新增了哪些落点（相对既有骨架）

| 落点 | 服务的流程 | 为什么必须有 |

| `00_PROJECT/06_对白/` | 对白编排（S6 台词侧） | 台词此前只活在剧本正文里，**配音单/音效单无处落** —— 05 拿不到结构化输入 |
