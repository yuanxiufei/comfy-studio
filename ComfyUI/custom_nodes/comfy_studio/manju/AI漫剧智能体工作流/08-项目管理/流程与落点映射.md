## 四、改流程时改哪里（避免"改一处漏两处"）

| 你要改的东西 | 改这里 | 改完必须跑 |
|---|---|---|
| 阶段划分 / 输入输出 / 门禁判据 | `生产流程规范（S0-S7）.md` | `python 工具/校验.py` |
| **项目目录 / 落点 / 命名** | ⭐ 本模块 `项目目录规范.md` + `07-智能体运行时/src/project.py` 的 `PROJECT_DIRS` | `python tests/test_project.py`（在 `07-智能体运行时/` 下） |
| 流水线**代码**（跑哪几步） | `07-智能体运行时/src/pipeline.py` 的 `STAGES` | 同上 |
| 某模块的**角色知识** | 该模块的 `00-主控智能体.md` 等 | `python 工具/校验.py` |

> ⚠️ **不要写 `python -m unittest discover -s tests -t .`** —— 本仓库路径含中文，
> 该命令会直接 `ImportError: Start directory is not importable`（2026-09-27 实测；路径在
> 交给 unittest 时被按 GBK 解码，成的乱码目录当然"不可导入"）。
> **本项目一律逐文件跑**：`python tests/test_<名字>.py`，每个测试文件自带 `__main__` 与自家汇总。
> 想一次跑完，在 `07-智能体运行时/` 下：
> `Get-ChildItem tests\*.py | ForEach-Object { python $_.FullName }`（看每行末尾的 `exit=`）——
> 每个文件都 `exit=0` 即无回归（**不写死"共 N 项"**：数字会随测试增加而失效）。

> ⚠️ **目录清单是两处**（规范文档 + `PROJECT_DIRS`），故 `tests/test_project.py` 里
> 有一条断言**逐项比对两者**：不一致直接红。这是「改权威层必须同步实体层」的机械兜底。
