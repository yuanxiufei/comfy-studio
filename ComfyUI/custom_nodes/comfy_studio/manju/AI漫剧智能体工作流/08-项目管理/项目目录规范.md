## 三、数据项规格（域 → 数据项 → 字段）

§一 §二 回答的是"**哪个目录放什么**"。可目录只是**域**；真要知道"这份东西属于谁、
该有哪些字段、谁有权改"，还得往下两层：**数据项**（域里的一类文件）与**字段**（文件里的表头）。

**字段不在这里复述**：本文件只钉"数据项叫什么名、属于哪一层、字段的权威在哪一份文件"。
把字段表再抄一遍，就是"同一知识两处维护"——改一处、另几处静默失效。

**「粒度」这一列是机器读得到的数据**：它同时是 `src/project.py::DIR_SCOPES` 的对应物，
由 `tests/test_project.py` 逐项核对（`spec_scopes_from_doc`）。它不是给人看的注脚 ——
面板要把 `01_剧本/` 下的`00_总纲/`（全剧级）与分集正文（分集级）分开摆，读的就是它。
所以**这一列不许写 `…` 省略**：省略式写法抽不出来，等于让面板猜。

| 域 | 落点 | 数据项（固定名 / 命名式） | 粒度 | 字段依据（权威在哪） |
|---|---|---|---|---|
| 剧本正文 | `00_PROJECT/01_剧本/` | `EP##-剧本.md` | 分集级 | `01-剧本文本/模板/剧本与角色小传模板.md` |

### 3.1 扩展位（怎么加东西不返工）

| 加什么 | 改哪几处 | 漏改会不会报 |
|---|---|---|
| **加落点** | `src/project.py::PROJECT_DIRS` + 本文件 §一 各一行 | ✅ `tests/test_project.py::test_dirs_match_spec_doc` 会报（逐项比对，顺序也算） |
| **改粒度** | `src/project.py::DIR_SCOPES` + 本文件 §三 那一行的「粒度」列 | ✅ `tests/test_project.py::test_scopes_match_spec_doc` 会报（逐项比对，键集与取值都算） |
| **加面板格** | `Comfy-Desktop/lib/comfy_studio/projects.py::PROJECT_SHELVES` | ✅ 新落点没被归到任何一格 → `shelf_gaps()` 报出来（有单测钉住为空） |
| **加数据项（文件）** | 本文件 §三 一行 + 对应模块的模板一份 | ⚠️ 靠人复核 —— 数据项那层没有机械守卫（只有落点与粒度有），**所以每加一项都要在这里留一行** |
| **改阶段 / 加阶段入口** | `src/project.py::STAGE_SPECS` + `../生产流程规范（S0-S7）.md` §一 + `流程与落点映射.md` §一 | ✅ `tests/test_stages.py` 会报（编号/名字/负责模块逐项比对；入口还要**真的存在**） |

## 四、迁移（v1 → v2）

v2 相对 v1 只动一处物理结构：`01_剧本/` 里的**全剧级**数据（大纲两份 + 角色小传）
收进 `00_总纲/`。其余落点、文件名、内容**一概不动**。

| v1 里在哪 | v2 迁到哪 | 动作 |
|---|---|---|
| `00_PROJECT/01_剧本/分集大纲与三表.md` | `00_PROJECT/01_剧本/00_总纲/分集大纲与三表.md` | 移动 |
| `00_PROJECT/01_剧本/_分集大纲.json` | `00_PROJECT/01_剧本/00_总纲/_分集大纲.json` | 移动 |
| `00_PROJECT/01_剧本/角色小传.md` | `00_PROJECT/01_剧本/00_总纲/角色小传.md` | 移动 |
| `00_PROJECT/01_剧本/EP##-剧本.md` | 原地 | 不动 |
| 其余 18 个落点 / `README.md` / `00_先读我.md` | 原地 | 不动 |

```bash
cd AI漫剧智能体工作流/07-智能体运行时
python main.py project migrate 我的剧          # 只移动，不覆盖，可反复跑
python main.py project migrate 我的剧 --预演    # 先看要动什么，不落盘
python main.py project new 我的剧 --升级        # 顺手补上 v1 时期还没有的落点
```

**三条保证**（都在 `src/project.py::migrate_project` 里，可读源码核对）：

1. **不覆盖**：目标已存在就**停下并如实报告**（连同两边内容是否相同），绝不静默覆盖 ——
   迁移脚本最坏的失败模式是把人写的正本换成旧副本。
2. **幂等**：源已经不在、目标已经在 → 报 `skip`，不算失败；反复跑结果一致。
3. **可预演**：`--预演` 走完整套判断，一行都不落盘。

> ⚠️ **迁移不检查引用**：`01_剧本/00_总纲/…` 这个新路径要同步到引用它的模块提示词与文档里
> （搜 `分集大纲与三表` / `角色小传` 即可）。`工具/校验.py` 的引用检查会兜一道底。

## 五、为什么这么分（两条判据，不是审美）

| 判据 | 体现 |
|---|---|
| **① 按「谁产出」分段，不按「文件类型」分段** | `00_PROJECT/` 是**跨模块**的流程与台账；资产段是 02 的；生产段是 03/04/05/06 的。按类型分（"所有图片放 images/“）会让**每集都要翻遍全库** |
| **② 「文本台账」与「二进制产物」分开** | `06_对白/`（编排方案，文本）与 `11_AUDIO/`（音频文件）分开 —— 前者要评审、要改、要 diff，后者是产物。混在一处会让 `git diff` 失去价值 |

**为什么 `09_SHOTS/` 与 `11_AUDIO/` 不在 `00_PROJECT/` 里**：
`00_PROJECT/` 的定位是**过程资料与账**（可评审、体量小）；
成片产物按阶段平铺在顶层，与 `08_STORYBOARDS/` 同级，便于按阶段整包交付。

## 六、一个项目从零到有

```bash
cd AI漫剧智能体工作流/07-智能体运行时
python main.py project new 我的剧          # 建目录 + 入口文件 + 填 03_台账/ 的空表
python main.py project check 我的剧        # 随时查：缺哪个落点、哪阶段还没产物
```

**填充顺序**（与 S0–S7 一致，详见 `流程与落点映射.md`）：

4. S1 起按 `流程与落点映射.md` 逐阶段推进，每阶段产物落在上表对应目录

## 七、命名通则

| 对象 | 约定 | 例 |
|---|---|---|
| 集号 | `EP` + 两位 | `EP01` |
| 分集产物 | 集号做**前缀**，便于排序 | `EP01-剧本.md`、`对白表_EP01.md` |
