## 〇、先分清三种"跑"（能不能让 agent 自己跑通？）

**结论：能跑，但不是"全自动"——而且不该追求全自动。**

| 模式 | 可行性 | 配置成本 | 说明 |
|---|---|---|---|
| **① 在对话里跑**（本 IDE / ChatGPT 对话 / Claude 项目） | ✅ **现在就能** | **零配置** | 把主控内容给 agent，它按流程逐步执行，**每步与你确认** |
| **② 部署成智能体跑**（GPTs / Coze / Dify） | ✅ 需一次性配置 | 中等 | 见 §三 四种组合方案、§四 各平台步骤 |
| **③ 全自动无人值守** | ❌ **不可行，也不必要** | — | 见下方三点原因 |

### 为什么"全自动"不可行也不必要

| 原因 | 说明 |
|---|---|
| **三门禁设计上就要暂停** | 剧本门禁 / 资产门禁 / 分镜门禁——**每一步交接前必须与用户确认**，这是防止"做错方向白做几十集"的机制，不是缺陷 |
| **外部生成是人工操作** | 出图（即梦/豆包）、出视频、出音乐（Suno）都发生在**外部平台**，要人工点生成、挑图、回传。<br>agent 的产物是**提示词与脚本**，不是成品媒体 |
| **版权类必须人确认** | `01-剧本文本/模板/OPEN-ISSUES.md` 明确规定：版权/授权类未决项**禁止 agent 自行判定**"应该可以商用" |

> **正确理解**：这是一套**人机协同**的生产流程——agent 负责"想清楚 + 写准提示词"，人负责"确认方向 + 按按钮生成"。
> **它能省掉的是"专业能力"（不会写分镜、不会配乐），不是"人工参与"。**

### ⚠️ 关于"agent 自己调用自己"的一个关键事实

模块之间的**交接包是文本约定，不是自动传参**：

```
05 交付包（文本） → 你/agent 把它作为 02 的输入 → 02 产出 → …
```

- **在同一个对话里**：agent 自己维护上下文，可以连续走完六模块
- **跨平台 / 跨会话**：需把**交接包原文**复制到下一个智能体（所以每个模块的交付包格式都要求含 ID 登记与未决项变动，正是为了能"整块搬运"）

### 现在就想起步？三步

```text
1. 给输入：一句话创意 / 三五百字梗概 / 小说 / 已有剧本
   （对应 01 模块的三条路线 A/B/C）
2. 让 agent 先做「启动准备」：建 ID-REGISTRY + OPEN-ISSUES
   （模板：01-剧本文本/模板/，这两步做完再动笔）
3. 按 00-总控路由.md 的链路走，到每个门禁处确认
```

> 若在本 IDE / 本地 Agent 里跑，agent 可**直接读写项目文件**（能真正落盘 `00_PROJECT/` 下的文档）；
> 若在 GPTs/Coze 里跑，则需把模板放进 Knowledge，由对话维护。

## 三、四种组合方案

### 方案 A｜只是做分镜（最轻）
```
部署：03-分镜导演/主工作流/storyboard-director-pro.md     → 要分镜表（含时长/转场/音效）
  或：03-分镜导演/视觉分镜引擎.md                          → 要视觉分镜图与中英 Prompt
适用：已有剧本与角色资产，只需要分镜表和提示词
```

### 方案 B｜做角色资产（美术前置）
```
部署：02-服化道/00-主控智能体.md
挂载：02-服化道/引擎/*.md + 02-服化道/模板/*
适用：要建立角色/服装/道具/场景资产库
```

### 方案 C｜全流程（推荐）
```
部署：00-总控路由.md（作为入口）
挂载：六个模块的 00-主控智能体.md（作为知识/工具）
      + 各模块 模板/ 引擎/
适用：从创意一路做到成片
说明：总控负责判定进哪个模块，模块主控负责执行
```

### 方案 D｜单点工具（最省）
```
按需只部署一个模块主控，用完即走
例：只部署 05-音乐音频/02-Suno歌词引擎.md 写歌（写歌词主力）
```

## 四、各平台具体步骤

### 4.1 ChatGPT GPTs

1. 创建 GPT → Configure 标签
2. **Instructions** 贴 `00-总控路由.md` 全文（或单个模块主控）
3. **Knowledge** 上传：各模块 `00-主控智能体.md`、`引擎/*.md`、`模板/*`
4. **Capabilities** 勾选 Code Interpreter（如需处理 YAML/表格）与 Image Generation
5. **Conversation starters** 建议填：
   - 我有一句话创意，帮我做一部漫剧
   - 生成角色三视图
   - 检查角色一致性
   - 写一首主题曲歌词

> ⚠️ `03-分镜导演/分镜导演-完整合并版.md`（31.4 KB）**已可进 Instructions**（GPTs 上限约 8 KB 字符量按字符算，31 KB 中英混排约 1.5 万字符，仍建议走 Knowledge 更稳）。稳妥做法：Instructions 放 `主工作流/storyboard-director-pro.md`，合并版走 Knowledge。

### 4.2 Coze / 扣子

1. 新建 Bot → 人设与回复逻辑 → 贴总控路由
2. 知识库 → 新建 → 上传各模块主控与模板
3. 插件 → 添加图像生成能力
4. 工作流（可选）→ 按六模块串成可视化流程

### 4.3 Dify

1. 创建应用 → Agent 或 Chatflow
2. 系统提示词 → 贴总控路由
3. 知识库 → 上传全部 md（分段建议按标题）
4. 工具 → 添加图像生成 / 代码执行
5. Chatflow 模式可把六模块做成六个节点

### 4.4 Claude Project

1. 新建 Project → Project Instructions 贴总控路由
2. Project Knowledge → 上传全部模块文件
3. **无原生生图** → 自动走"可执行 Prompt 模式"（符合 `02-服化道` RULE-001 的降级分支）

### 4.5 本地 Agent / 本 IDE

1. 直接把 `AI漫剧智能体工作流/` 目录作为工作区
2. 在对话中指定："按 `02-服化道/00-主控智能体.md` 执行"
3. 有图像生成工具时，RULE-001「图像优先」可真实执行

## 四·补、项目级前置：两份共享文档（不部署，但必须先建）

以下两份**不是给 agent 部署的**，而是**项目运行时**要用的数据文件。它们在 **01 剧本阶段建纲时创建**，03/02/04/05/06 全程读写。

| 文档 | 模板位置 | 落盘位置 | 作用 |
|---|---|---|---|
| **ID-REGISTRY.md** | `01-剧本文本/模板/ID-REGISTRY.md` | `AI_DRAMA_PROJECT/00_PROJECT/` | 全剧 ID 一次性分配（含未出场角色预留），号位不复用 |
| **OPEN-ISSUES.md** | `01-剧本文本/模板/OPEN-ISSUES.md` | 同上 | 外部依赖（版权/授权/平台/预算）启动即登记 |

### 部署时怎么处理

| 平台 | 做法 |
|---|---|
| **ChatGPT GPTs** | 把两个模板放进 Knowledge，让 agent 需要时读取格式 |
| **Coze / Dify** | 同上（知识库/数据集） |
| **本地 Agent / 本 IDE** | 直接在项目里建这两个文件，agent 读写真实文件 |
| **纯 prompt（无文件能力）** | 在对话中维护，每轮交接时复述当前 ID 表与未决项 |

### 为什么必须提到部署步骤里

这两个机制的存在与否不影响 agent「能不能跑」，但决定**长流程会不会垮**：

```
缺 ID-REGISTRY → 第 3 集出现新角色时号段冲突 / 引用断裂 / 下游返工
缺 OPEN-ISSUES  → 全片做完才发现音乐不能商用，配乐整体重做
```

> ⚠️ **判据**：如果你的项目只做**单集**，这两份文档可选；只要做**多集**，必须建。

## 六、常见问题

**Q：总控和各模块主控会不会冲突？**
A：不会。总控只做路由判定，不进具体执行；判定后由模块主控执行。总控的输出格式中已要求"先给出路由判定"。

**Q：可以只改模块不改总控吗？**
A：可以。总控只依赖模块的**职责边界**与**ID 协议**，模块内部规则变更不影响调度。

**Q：02-服化道 的 V2.0 规格能改吗？**
A：该文件是与源规格逐字节一致的副本，**建议不改**。要扩展请新增 `引擎/` 下文件，或在 README 注明差异。

**Q：没有图像生成能力怎么办？**
A：自动降级为"可执行生图 Prompt 模式"，输出完整 17 项提示词（中文 + 英文 + 负面词 + Asset Lock），可直接复制到 Midjourney / SD / 即梦使用。

**Q：ID 命名能改吗？**
A：不建议。跨模块交接依赖统一前缀，改动会导致断链。规范权威在 `00-总控路由.md` §四，实例登记在 `01-剧本文本/模板/ID-REGISTRY.md`。

**Q：改了主控，还要改什么？**
A：**必须同步「实体层」**——这是本项目最易踩的坑。权威内容分三层，只改上面两层会导致用户实操时拿到的仍是被取代的旧格式：

```
① 事实来源层  规格 / 各模块 00-主控智能体.md
② 规则层      引擎/*.md · 模块 README.md
③ 实体层      ← 最易漏！模板/* · 可部署的合并版/总集 · 项目骨架/ 下 _README
```

改完请跑 `python 工具/校验.py` 自动检出漏同步（详见 `工具/README.md`）。
