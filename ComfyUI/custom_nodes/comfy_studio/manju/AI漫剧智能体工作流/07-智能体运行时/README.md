# AI漫剧智能体运行时

> **工作流里每个流程模块，都是一个可独立运行的 agent** —— 本目录是它们的**通用运行时**。

**它是 `AI漫剧智能体工作流` 的代码实现**（位于工作流内 `07-智能体运行时/`），
不是替代品——**规则从工作流实时读取，本项目不复制一份**（见 §三）。

---

## 一、30 秒上手

```bash
cd 07-智能体运行时
python main.py doctor                    # ① 环境自检（先跑这个）
python main.py agents                    # ② 看 7 个 agent 全貌

python main.py init script               # ③ 独立启动某个 agent（01 剧本）
python main.py run script "废土末世，40集"  # ④ 用它干活
python main.py route "这场戏怎么拆分镜"      # ⑤ 不确定进哪个 → 让总控判定
python main.py gate all                  # ⑥ 三门禁一览

python main.py flow --状态                # ⑦ 全流程体检（每阶段有多少产物，不跑生成）
python main.py flow --从 分镜             # ⑧ 从剧本一路跑到成片（S0/S1 要模型，默认从分镜起）
```

> ✅ **无需任何 API Key** —— 未配 Key 时输出**可直接粘贴的调用包**
> （System Prompt 已按该 agent 装配好，粘进 ChatGPT/Claude/CodeBuddy 即可）；
> 配置 `MODEL_API_KEY` 后自动变成真实模型调用。

## 二、⭐ 七个 agent（每个都可独立运行）

| 编号 | key | agent | 职责 | 门禁 |
|---|---|---|---|---|

## 三、⭐ 与工作流的关系（**必读**）

### 3.1 只读**工作流**、绝不复制规则

| 加载的权威内容 | 来源 |
|---|---|
| 每个 agent 的**角色知识**（主控 + 引擎） | 各模块的 `00-主控智能体.md` 等 |
| **初始化指令 / 输出纪律 / 输入分流** | 从上述文档里**按段抽取**（工作流自带体例） |
| **资产 ID 命名与交接协议** | `00-总控路由.md` §四 |
| **三门禁判定标准** | `00-总控路由.md` §五 |
| **全局一致性守护（四张单子 + 漂移检测）** | `00-总控路由.md` §六（漂移检测**已实现为 `drift`**，见 §四） |
| 02 的负面词 / 三视图硬标准 / 资产卡字段 | `02-服化道/引擎/*` + `模板/ASSET_CARD.yaml` |

**为什么必须这样**：把规则复制进代码，就会出现**两处维护、迟早发散**
—— 这正是工作流质量守则 §2「单一权威来源」要防的事。

### 3.2 ⭐ 通用是怎么做到的：**声明式注册表**

新增或改造一个流程 agent = **在 `src/registry.py` 加一条**。
之后 CLI、路由、交接清单、门禁、文档清单会**自动**支持它 —— **零代码改动**。

```python
AgentSpec(
    key="storyboard", no="03", name="分镜导演", dir="03-分镜导演",
    role_docs=[...],      # 扮演它必须读的文档
    ref_docs=[...],       # 按需加载的素材
    outputs=[...],        # 交付物
    gate="分镜门禁",       # 门禁 + 判据关键词
    triggers=[...],       # 用户这么说 → 进这个 agent
)
```

### ⭐ `drift`：把 §六 的那句话变成代码

`00-总控路由.md` §六 原文里有一句：

> **漂移检测**：每当有模块交付，检查其引用的 ID 是否都在 ID 总表中…**是否自造了未登记 ID**。

**这是机制，不是规则** —— 在此之前它只是被原样粘进 System Prompt（"让模型自己记得"）。
而"ID 在不在总表里"是**纯确定性的**，用代码做必然更可靠。`drift` 就是它的实现：

```bash
$ python main.py drift output/EP01-分镜表.md
  ❌ 未登记 ID（自造 / 笔误 / 引用不存在的资产）：CHR_099 · EXP_CHR001_警惕
  ❌ ID 格式不合规范：ENV_01   ← §四 要求 `ENV_<3位>`，此处是 2 位
  ❌ 风格锚点与权威规则不一致（**画风漂移**）：光影锚点被改成 harsh contrast, warm palette
  ● 外来前缀（本项目无总表，不判定）：SHT_ → 归 03-分镜导演 管
  ⚠️ 未核验：交接清单里人手写的 `风格锚点：` 字段（自由文本，无法确定性比对）
```

| 判据 | 依据 |
|---|---|
| 未登记 ID（自造 / 笔误） | §六「是否自造了未登记 ID」 |
| 格式不合 §四（如 `ENV_01` 只 2 位） | §四 `ENV_<3位>` |
| 一号两类型 | 同一 ID 落在两个类型目录 / 总表类型 ≠ 卡片实际类型 |
| 两张单子不一致 | `id_registry.json` 与 `assets/` 实际目录对不上 |
| **风格锚点漂移** | §六「防全片画风漂移」+ `VISUAL_BIBLE.md` §4.8「**一字不改**」 |
| 孤儿资产 | 登记了但未见任何交付物引用（ℹ️ 提示，**不算错**） |
| **外来前缀** | `SHT_`/`VID_`/`AUD_` 归 03/04/05 管，本项目**无总表 → 不判定**（避免天天误报） |

### 风格锚点怎么验（不需要那张不存在的表）

§六 说比对「风格锚点表」，但那张表的模板被指到 `TURNAROUND-STANDARD.md` §七 ——
**指错了**（§七 实际是「光影设计的三个来源与分工」）。
风格锚点的**权威定义**在 `02-服化道/模板/VISUAL_BIBLE.md` **§4.8**
（「风格 DNA / 风格锚点」+「全片所有 prompt 末尾强制追加，**一字不改**」）。

而**本项目每条提示词里都真的带着这段锚点**，值来自权威规则。于是：

| 核验对象 | 判据 |
|---|---|
| 每个交付物里的 `CINEMATIC QUALITY …` 与 `Quality targets …` | 应与**权威规则里的锚点逐字相同** |
| 各交付物之间 | 也应逐字相同 |

这样就**不依赖那张表**也能查出画风漂移 —— 且能在**交付当场**报出来。

> ✅ **该错引用已订正**（2026-09-24，三处）：§六 / 根 README 对照表 / `ID-REGISTRY.md`
> 原本把风格锚点表指向 `TURNAROUND-STANDARD.md` **§七** —— 实为**差一节**：
> 画质参数与电影感具体化就在该文件 **§六**。现权威来源写作
> 「`VISUAL_BIBLE.md` §4.8（画风/LUT）+ `TURNAROUND-STANDARD.md` §六（画质参数）」。

### ⭐⭐ 通用性：**任何一部小说都能跑**（不绑定题材）

**问题（实测量化过）**：补全此前靠**固定题材表** —— 角色 11 题材 ·
**服装只 4 类** · **道具只 5 类** · 批量 5 个世界观池。实测 5 种输入的命中情况：

| 输入 | world | 服装预设 | 道具预设 | 场景预设 |
|---|---|---|---|---|
| 废土女佣兵 | `wasteland` ✅ | — | — | — |
| **民国谍战（旗袍/密码本）** | **空** ❌ | **无** | **无** | **无** |
| 仙侠剑修（青衫/飞剑） | `ancient` | **无** | 剑 ✅ | **无** |
| 都市言情（西装/腕表） | `modern` | **无** | **无** | **赛博都市街道** ❌ |
| 现代刑侦（夹克/配枪） | `modern` | **无** | 枪 ✅ | **无** |

→ 服装预设 **5 种全部没命中**，于是「穿**旗袍**的女特工」被补成
「**棉**质三层功能服装」—— **把用户给的事实换成了预设里的假具体值**。
根因两条：① `costume`/`prop`/`scene` 只用 `parsed.raw` **查预设**，
**从不使用** `parsed.clothing_hints` / `equipment_hints`；② 预设被当成**唯一来源**。

**解法（`src/generic.py`）—— 三条原则**：

| 原则 | 做法 |
|---|---|
| **① 用户原话 > 预设值** | 「这一部小说的事实」优先于「我预先想到的题材」 |
| **② 按「语法」抽词，不按「词表」** | 「穿/着/戴 + X」「携带/握着 + X」「在 + 场所」——**不需要认识那个词**也能抽出来。加词表是打地鼠（今天加"旗袍"，明天"襦裙"又不行） |
| **③ 抽不到就**如实标注**，不假装具体** | 兜底值照给（prompt 要用），但在说明里**逐项标注哪些是兜底** —— 不让人以为「棉」是从描述里识别出来的 |

**执行顺序即优先级**（三步，缺一不可）：
```
① 先写「从原文抽到的」   → 用户原话赢
② 再跑题材预设（**仅当真命中时**）→ 命中则更具体
③ 最后写「中性兜底」     → 只填真空白，并如实标注
```
> ⚠️ 第 ② 步的「仅当真命中时」是关键：未命中会返回 `DEFAULT_COSTUME`（棉/深灰黑）
> 这类**"看起来具体、其实与题材无关"**的值 —— 让它们赢，就会把「旗袍」配上「棉」。

**实测 8 种题材**（含 5 种表外）：

```
民国谍战 / 仙侠 / 都市言情 / 现代刑侦 / 古代宫廷 / 蒸汽朋克 / 民国道具 / 表内废土
  → 英文 prompt 中文字符数 **全部为 0** ✅
  → 用户原话（旗袍/道袍/西装/夹克/袆衣/密码本…）**都进了中文字段** ✅
```

同时补了两处词表（**材质有限，扩充正当**）：`MATERIALS` 加「丝/丝绸/缎/纱/呢/绒/锦…」
（此前缺它们 —— 而「丝质旗袍」会因 `tr('丝')` 原样返回中文而把中文送进英文）；
场所后缀加「洋行/当铺/客栈/衙门/书院…」。

**测试**：`tests/test_generic.py`（**91 项**）—— 含「表外题材」「英文纯度」「类型判定」三类断言。
2026-09-27 补 **⑯「修改动词表只有一份」**：`router.MODIFY_WORDS` 曾是 `nl_parser.MODIFY_VERBS`
的副本（少一个「减掉」），已删除并钉住「同一对象 + 每个动词都判 modify + 修改优先于查询」。

#### ⭐ 类型判定：**能靠语法判的，绝不靠名词表**

原实现判"这是什么资产"**只看词表**（`PROP_WORDS` / `SCENE_WORDS` / …）。
于是凡是**我们没写进表**的名词，一律落到 `character`：

```
python main.py "设计一柄油纸伞"
  ❌ 旧：CHR_002 ｜ 设计一柄油纸伞 ｜ character     ← 连资产名都是整句话
  ✅ 新：PRP_001 ｜ 油纸伞        ｜ prop
```

**这是「任何一部小说都行」最大的漏洞** —— 用户换个题材，他的名词就不在表里了。

现改为**三道结构信号**（全部与题材无关，汉语语法事实）：

| 信号 | 判什么 | 例 |
|---|---|---|
| **量词**（`套件身袭` / `把支柄台只副盏枚…`） | 服饰 / 器物 | 「设计一**柄**油纸伞」→ 道具；「设计一**套**旗袍」→ 服装 |
| **场所字结尾**（`PLACE_SUFFIX`，**字**表不是词表） | 场景 | 「民国上海洋行的大**厅**」→ 场景 |
| **职业词 + 人物信号** | 角色（护栏） | 「一位药铺的掌柜」→ 角色 |

**两条语法事实贯穿始终**：
1. **汉语名词短语的中心语在最后** → 判据是「**结尾**」而不是「**含**」。
   实测：「一位**药铺**的掌柜」因中间有「药/铺」被误判成道具/场景；
   「一个老练的**船**工」同理。
2. **「把」多半是介词不是量词** → 把字句要排除。
   实测（**冒烟测试抓出来的**）：「把她的头发换成银白色」被判成道具 →
   指代「她」被解析到 `PRP_001` 上。

> ⚠️ **已知歧义（如实记录）**：「把他的义肢换成机械臂」——
> 「义肢」在本项目里**既是角色部件、也是独立道具资产**，判成哪种都有道理。
> 当前判为 `prop`（句尾「机械臂」命中词表）。**不把它写进测试** ——
> 把歧义当唯一正确答案来测是假测试。要定的话得先确认语义。

#### 中译英词表：**两层**（内置措辞层 + 外挂通用词典）

手写 `ZH2EN`（168 条）+ `OCCUPATION_EN`（43 条）的根本问题不是"少"，
而是**它变成了一道闸门** —— 查不到的词进不了英文提示词。这正是
「任何一部小说都行」被卡住的地方。

| 层 | 来源 | 职责 | 优先级 |
|---|---|---|---|
| ① 内置 | `prompt_engine.ZH2EN`（手工） | **为 prompt 调过的措辞** | ✅ 优先 |
| ② 外挂 | `词库/zh2en.json.gz`（**CC-CEDICT** 生成，61,880 条） | **广度**：只补内置没有的词 | 兜底 |

**实测收益**（统计「因译不出而被丢掉的字段」）：

| | 丢掉字段数 |
|---|---|
| 只有内置 | 9 |
| **装上外挂** | **2** |

丢掉的是 `线人 / 巡捕 / 掌柜 / 船工 / 大厅 / 弄堂阁楼` —— 全是**表外题材**的词。

**重新生成**（`gzip` 是标准库，**运行时仍零第三方依赖**）：

```bash
python 工具/生成词库.py            # 自动下载 CC-CEDICT（约 4 MB）
python 工具/生成词库.py --预览      # 只看统计与样例
```

> ⚠️ **许可**：CC-CEDICT 采用 **CC BY-SA 4.0，必须署名**。
> `词库/README.md` 与生成物的 `_meta` 里都写了来源/许可；**再分发时必须保留**。

> ⚠️ **目录名是 `词库/` 不是 `data/`** —— 仓库根 `.gitignore` 的 `data/` 没锚定，
> 会连带忽略任何层级的 `data/`（后果很隐蔽：文件**静默不入库**）。

**测试**：`tests/test_dict.py`（**33 项**）—— 含「内置优先」「中译英必须补空格」
「词典损坏不静默」「署名许可存在」四类断言。

#### 同一条原则也用在 `world` 与**批量**

| 位置 | 原做法（绑死） | 现做法（通用） |
|---|---|---|
| `world` 识别 | **只有 11 个题材键**，未命中即空 | 未命中**回退到时代词**（「民国」「清朝」「未来」…）→ world 是**自由文本** |
| 资产名 | world 空 → 拼成「主角-**未定**」 | world 空**不拼**（那串会污染名字，"没识别出"由 `world=""` 本身承担） |
| 批量 NPC 身份 | **5 个池**，未命中静默套用 | **用户给的清单 > 题材池 > 题材无关的通用身份**，且未命中**明说** |

> ⚠️ 原实现里 `default.jobs` 写的是「**主角 / 伙伴 / 对手 / 导师 / 路人甲**」——
> 那是**叙事角色位**，不是**剧中身份**。批量产出会得到
> 「一个24岁的民国谍战**主角**」这种把叙事标签当身份的名字。

### ⭐ 锁定系统 / 修改引擎（`LOCK-SYSTEM.md` §三「修改执行四步（**强制**）」）

该文档自述「**这是连续生产的核心机制**」，其 §三 四步此前**一步都没实现**
（`AssetCard.locked` 字段定义了但无人写入）。现已落地：

| §三 步骤 | 实现 |
|---|---|
| STEP 1 解析指令 → LOCK/MODIFY 映射 | `lock.parse_directive()` —— 读 §二 的 17 行「用户说 → 解释」表（**两种表达形式**都认：`K=V` 与 `…全 LOCK`）|
| STEP 2 **冲突检测** | `lock.detect_conflicts()` —— 并入 Gate 报告 + 输出说明 |
| STEP 3 受控生成 | 锁定项写进 `card.locked`（进 prompt 一致性约束）|
| STEP 4 **记录变更** | `lock.append_entry()` → `output/CHANGELOG.yaml`（`changed`/`unchanged`/`reason`，字段与模板**逐字对齐**）|

**默认锁什么**（依权威，不是猜）：

| 来源 | 内容 | 落到本项目 |
|---|---|---|
| `LOCK-SYSTEM.md` §四·补 A「**终身固定核心识别特征（100% 不可改动）**」 | 核心骨相 · 五官轮廓 · **瞳色** · 标志性永久识别点 · 微表情习惯 | `card.locked` = `LOCK_FACE` / `LOCK_CHARACTER` / `LOCK_EXPRESSION` |
| 同文件 §四·补 B「剧情适配变量项（**各状态卡之间可不同**）」 | 发色/发型/毛发 · 身形/体态 · 穿搭/配饰 | `card.editable` = `LOCK_HAIR` / `LOCK_BODY` / `LOCK_COSTUME` / `LOCK_PROP` |

于是最该报的那一类约束真的会响：

```bash
$ python main.py "把她的瞳孔换成褐色"
  ⚠️ [LOCK_CONFLICT] 锁定项冲突：**瞳色**（本次将改动：eye_color）——
     §四·补 A 列为「**100% 不可改动**」；原文：「修改本组 = **重新设计角色**，
     必须递增主版本号并通知全项目」。
     若只是当前状态（造型/服装/表情）变化，请改 `stage_variables` 而非这些字段
$ python main.py "把她的头发换成银白色"
  （不报 —— §四·补 B 明文「发色变化」是可变的）✅ 不误报
```

> ⚠️ **修复了 6 处"抄文档举例当默认值"**：6 个 agent 各写了一套默认锁定集，**每套都错** ——
> `character` 抄了 `ASSET_CARD.yaml` 第 104 行**注释里的举例**（`例：["FACE","HAIR","BODY"]`，
> 且 HAIR 不在 §四·补 A、漏了真正不可改的瞳孔）；`costume`/`prop` 用了
> `CUT`/`LAYER_ORDER`/`STRUCTURE` 这类**不是 §一 `LOCK_*`** 的名字；`scene` 把 §32 的
> **中文空间要素**当锁定项；`expression`/`pose` 则**语义反转**
> （`locked = editable = MUTABLE_PARTS`，而注释写着"只有这几项**允许**改"）。
> 现已统一为从 §四·补 A/B 推导，并有自检（`validate_field_map` / `validate_lifelong_map`）
> 保证代码里的 `LOCK_*` 名一定在 §一 清单内。

**批量的实现取向**（值得说明）：**不做"批量专用流水线"**，而是把「一次 10 个废土 NPC」
**展开成 10 条自然语言请求**，各自走**正常创建流程** —— 于是每一项都自动获得同一套
Gate / 指纹 / 版本 / 落盘，不会出现「批量生成的与单个生成的不一样」这种最难查的偏差。
本地池按世界观分组（废土/赛博朋克/科幻/奇幻/通用），保证 10 项**身份/年龄/识别点互不重复**。

**全景基准的两种用法**：传场景描述 → 新建并直接出全景；传 `ENV_00X` → **派生**
一张全景基准卡（ID 加 `_PanoramaBase` 状态位）。推荐出图参数（§4.6 原文的**真实参数**：
`5824×2880` · `DPM++ 2M Karras` · `28–35` 步 · `CFG 7–9`）会随卡片一起给出。

**六角度的关键机制**（§4.1 原文警告：**「不建此表 → 各角度独立从文字生成 → 空间必然漂移」**）：

| 铁则 | 本项目的落实 |
|---|---|
| ① **必须先出 S01**（纯文字 prompt） | 先出 S01，其路径存为该场景的 reference；**S01 永远不带参考图**（带图就不是"基准"了）|
| ② **S02–S06 全部以 S01 为 reference_image**，追加 `same scene as reference` | ✅ **真的挂图**：把 S01 的**图**传给 Provider 的图生图接口，不只是写进 prompt |
| ③ 每张只写该视角**实际可见**的物品 | 提示词显式写「render ONLY what is visible from here」+ 该角度覆盖范围 |
| ④ 材质词/颜色词从场景圣经**复制、不替换同义词** | 六个角度**复用同一个 SceneDNA**，从机制上保证用词一致 |

并产出 §4.1 要求的那张**场景资产库索引表**（含分镜选图规则）——
它不是文档装饰，而是机制的一部分。

### ⭐ 参考图（image-to-image）已实现

| Provider | 无参考图 | 有参考图 |
|---|---|---|
| `mock` | 占位图 | 把参考图**混入配色**并画左上白条 —— 使「参考图有没有真的传进来」**可用产物验证** |
| `openai` | `POST /images/generations`（JSON） | `POST /images/edits`（multipart，字段 `image[]`） |
| `stability` | `files={"none": ""}` | `mode=image-to-image` + `strength`（默认 0.55） + `image` 文件 |
| `comfyui` | 驱动**本机 ComfyUI**：`POST /prompt` 入队 → 轮询 `/history` → `/view` 取图 | 工作流里有 `LoadImage` 节点才支持（先 `POST /upload/image`）；**没有就报错**，绝不降级成纯文字 |

> **`comfyui` 是唯一"自带节点图"的后端**：它不调用外部服务，只把提示词**注入你自己的工作流**——
> 注入四处：`KSampler.positive` 所指 `CLIPTextEncode` 的 `text`、`.negative` 所指的 `text`、
> latent 节点的 `width`/`height`、`KSampler.seed`；其余节点（模型 / LoRA / VAE / 采样器）**照工作流原样**。
> 因此**换配方 = 换工作流文件，代码一行不动**。配置见 `config.json` 的 `image.comfyui` 一节
> （`workflow` 填一张**节点式**工作流 JSON 的绝对路径），也可用 `COMFYUI_WORKFLOW` / `COMFYUI_BASE_URL` 覆盖。
> **不需要任何 API Key**。注入点一律**靠连线定位**（不靠节点 id —— 你在 ComfyUI 里重画一次，id 就全变了）。
> seed 留空时由提示词哈希派生：**同词同 seed**，这是《ComfyUI 出图流程》§五 的一致性第 1 条。

通用入口：**任何**生成都可以挂参考图（保形象/空间一致）：

```bash
python main.py "把她的眼睛换成琥珀色" --reference output/images/CHR_001/v001.png
```

> ⚠️ **参考图不存在时会明确报错**，不会静默降级成纯文字生成 ——
> 「挂图失败被吞掉」的后果正是 §4.1 警告的「各角度独立从文字生成 → 空间必然漂移」，
> 而用户会以为已按铁则执行。

> ⭐ **用户不需要使用固定格式**（蓝图的核心立场，已落到实现）：
> CLI 接受任意自然语言、任意顺序、中英混排 —— `"一个30岁的废土女佣兵"`
> 与 `"画个女佣兵，机械臂，废土风，三十来岁"` **等价**。
> **资产类型**（角色/服装/道具/场景）与**意图**（创建/修改/查询）都由运行时自动判定，
> 判不准时**只问一句**（工作流 §八·5），绝不要求用户按模板填写。

### 两种形态的实现差异

| | **联动型**（7 个，`manju-0N-*`） | **移植型**（6 个） |
|---|---|---|
| 来源 | 手写薄封装 | ⭐ **逐字移植** `智能体搭建参考md/` 6 份规格 |
| **代表谁** | ⭐ **本仓库的权威规则 + 代码** | ⭐ **对外迁移配置**（规格自己写明「迁移到其他平台」） |
| 规则 | **只给路径**，让它自己读工作流 | **全文内联**（脱离本仓库也能跑） |
| ID / Gate / 漂移 | ⭐ **调 `python main.py`**（代码判） | 规格里怎么写就怎么写 |
| 重新生成 | 手工维护 | `python .codebuddy/agents/_build.py`（规格改了重跑，**不手改生成物**） |

> ⚠️ **「自动/手动」的判据与"谁权威"无关** —— 权威边界是**按用途**分的
> （本仓库内以工作流为准；要迁出以参考 md 为准，两者不自动同步，详见
> `智能体搭建参考md/README.md`）。
> 而自动入口的取舍判据是**任务能力**：**有代码支撑的留联动型**（一致性由代码强制，不是靠模型记得）、
> **内容互补的留移植型**（如 01/03/05 的规格远厚于工作流对应文档）。两件事分开看。

### ⭐ 裂解原则：**同一份规格，两种加载方式**

原始规格（`智能体搭建参考md/` 6 份）是**给"没有工具的模型"**写的 —— 所以它必须
把规则**全文内联**。而子智能体**有文件工具**，于是：

| 内容 | 移植型（自包含，13 个里的 6 个） | 联动型（与本仓库代码联动，7 个） |
|---|---|---|
| 角色 / 职责 / 交付 / 门禁 | **内联**（短） | **内联**（短） |
| 权威规则正文 | ⭐ **全文内联**（脱离本仓库也能跑） | ⭐ **只给路径，让它自己读** |
| 参考素材（长表/示例） | 内联（随规格一起搬） | 只给路径 |
| ID 协议 / Gate / 漂移检测 | 规格里怎么写就怎么写 | ⭐ **调 `python main.py`**（代码判） |

> ⚠️ **为什么联动型必须"只给路径"**：本项目第一纪律是「规则**只读工作流，不复制**」。
> 若把规则抄进它的 System Prompt，就变成**同一知识两处维护** ——
> 工作流一改，抄的那份就悄悄过时。
>
> ⚠️ **为什么移植型反而要"全文内联"**：它的目的就是**脱离本仓库独立可用**
> （规格自己写着「适用：Custom GPT / Agent / System Prompt」）。
> 两者**各有用途**：独立可用 vs 与本仓库代码联动。

### 校验（**路径唯一性**这一类坑）

```bash
python tests/test_agents.py      # 222 项（含用户级安装器的纯函数自检）
```

它检查五件"看起来对但实际错"的事：

1. **frontmatter 能否被 YAML 解析** —— 描述里的冒号/引号会**静默**破坏它；
2. 必填字段（官方：`agentic` 模式 `name` + `description` 必填）与 `name == 文件名`；
3. ⭐ **引用的路径是否指向唯一一份** —— 工作流里 `00-主控智能体.md` 有 **5 份**
   （01/02/04/05/06 各一份），**只写文件名会让 agent 读错模块的文档**，
   而那看起来"完全正常"。同理校验 `main.py <cmd>` 是否真实存在。
   （移植型反过来：校验它**可追溯源规格**且**未夹入本仓库专属路径**，即自包含性。）
4. ⭐⭐ **自动入口名册** —— 每个模块的 `agentic` agent 必须**恰好等于名册登记的那几个**
   （多出也报、缺失也报，名册里有幽灵也报）。这防的是"同一职责又冒出一个自动入口"。
5. ⭐⭐ **生成物 == 按源规格重算（逐字）** —— 抓两类**都不会报错**的静默问题：
   · **改了规格却忘了重跑 `_build.py`** → 部署的 agent 仍是旧规则；
   · **有人手改了生成物** → 下次生成会被覆盖，改动**静默丢失**。
   顺带查**孤儿生成物**（有文件、无 `SOURCES` 条目 = 无源可再生成）。

> ⚠️ 第 4 条我第一版写成"每模块**恰好一个**"，结果**当场被自己抓出来**：
> 模块 05 的两份规格**职责本就互斥**（写歌 vs 声线/环境声），两个自动入口是合理的。
> 把"恰好一个"当铁律会**逼着把互斥的职责合并或砍掉**。故改为**名册**
> （新增/移动自动入口必须改那张表 = 人工确认过职责不重叠）。

> ⚠️ **检查器自己也要被检查**：本测试第一版把 Windows 的 `\` 当成 `/` 做后缀匹配，
> 于是把 18 条**真实存在**的路径全判成"找不到"，差点让我去改对的代码。

### 部署到**用户级**（`~/.codebuddy/agents/`）

上面 13 个都是**项目级**（只在 agent-voide 里生效）。要让它们在本机**所有项目**里可用，
用 `.codebuddy/agents/_install_user.py` 装到用户级：

```bash
python .codebuddy/agents/_install_user.py            # 安装（覆盖同名）
python .codebuddy/agents/_install_user.py --校验      # 只比对不写盘；不一致 → 退出码 1
python .codebuddy/agents/_install_user.py --卸载      # 撤掉本批
python .codebuddy/agents/_install_user.py --仅移植型  # 只装参考 md 那 6 个自包含 agent（装/校验/卸载要带同一口径）
```

⚠️ 它**不是复制**，做三件事（每件都对应一个静默失效的坑）：

| | 做什么 | 不做的后果 |
|---|---|---|
| ① | **路径绝对化**：`AI漫剧智能体工作流/…`、`07-智能体运行时/…` → 绝对路径 | 用户级 agent 会在**别人的项目**里被调用，那时 cwd 不是本仓库 → 相对路径失效，agent 读不到权威文档 |
| ② | 正文最前声明**路径基准**（仓库根 / 工作流根） | 裸写法（`02-服化道/…` 相对**工作流根**、`01-声音设计引擎.md` 相对**模块目录**）**无法全局替换**，硬替换会改写错语义 |
| ③ | 标注**派生关系**（权威源 + 重装命令） | 直接改用户级那份，下次安装会**静默覆盖**它 |

⚠️ **路径替换必须单遍完成**：分遍做（先 `AI漫剧智能体工作流` 再 `07-智能体运行时`）时，
第二遍会命中第一遍刚生成的那段，得到
`…/AI漫剧智能体工作流/D:/…/AI漫剧智能体工作流/07-智能体运行时` ——
**不报错、还挺像路径**。故安装器内置签名自检，`tests/test_agents.py` 里也钉住了
「**单遍 + 幂等** + 注记必须声明基准、目录不存在时必须索要（禁止猜路径）」共 7 项。

⚠️ **用户级副本 = 派生物**：改规则一律改**项目级那 13 个源文件**（移植型还要先改
`智能体搭建参考md/` 的规格），再重跑安装 —— 校验分两处，
项目级看 `tests/test_agents.py`，用户级看 `--校验`（后者是**机器相关**的，
故 `test_agents.py` 只测纯函数；本机若装过，它会**顺带核对**那份副本是否已陈旧）。

> ### ⚠️ 为什么 `verify` **不做**"图与图是否同一个人"的判定
>
> 那属于**图像语义比对**。没有视觉模型时，用像素/直方图硬凑出来的"一致/不一致"
> **很可能是错的** —— 而这一项偏偏最不能错：**脸崩了却报一致，比不检查更糟**
> （会让人放心地进入下一阶段）。
>
> 故 `verify` 只核验客观项（文件在不在、尺寸对不对、提示词有没有中文残留、
> 负面词权重标记在不在、六角度与索引表齐不齐），并**显式列出未核验项**，
> 避免"verify 通过 = 一切都对"的误解。等接入真实视觉模型再做语义比对比现在硬做更负责。
