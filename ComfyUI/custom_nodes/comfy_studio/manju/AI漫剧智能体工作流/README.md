```
【01 剧本文本】剧本创作 / 小说改编
        ↓ 交付：剧本 + 角色小传 + 分集大纲
        ↓ ★门禁1 剧本门禁
【02 服化道】世界观 → 角色资产 → 场景资产 → 风格锁定     ← 美术前置，防画风漂移
        ↓ 交付：VISUAL_BIBLE + 资产库（ID化）+ 风格锚点
        ↓ ★门禁2 资产门禁
【03 分镜导演】导演定调 → 分镜拆解 → 提示词
        ↓ 交付：九列分镜表 + 提示词包
        ↓ ★门禁3 分镜门禁
【04 视频生成】分镜转视频（尾帧连贯 + 转场）
        ↓
【05 音乐音频】配乐 / 配音 / 调音
        ↓
【06 合规审核】过审检查 → 发布
```

**三门禁（跨模块）：**

| 门禁 | 位置 | 通过标准 |
|---|---|---|
| ① 剧本门禁 | 05 交付时 | 分集结构完整 + 角色小传齐全 + 钩子设计到位 |
| ② 资产门禁 | 02 交付时 | VISUAL_BIBLE 锁定 + 角色过一致性 Gate + 风格锁定表齐全 |
| ③ 分镜门禁 | 01 交付时 | 九列完整 + 引用资产 ID + 每镜有叙事目的 |

**模块内部闸门（02 服化道）：** 世界观锁定 · 角色一致性 · 一致性检查

## 五、质量守则（防臃肿）

> 依据用户反馈：「借鉴有用的，不要搞得很垃圾」。本项目明确三条纪律。

### 1. 不整段复制，只提炼可用部分

借鉴外部资料时，**提取可复用的词汇、公式、机制**，删除重复表述与冗余指令。

| 反面案例 | 正面做法 |
|---|---|
| 把 35KB 规格原文整份复制进模块 | 提炼为 23KB 可用版，原文移入 `_规格原文/` 存档 |
| 把 10 个源 skill 全文再内嵌进合并版（77KB） | 合并版只留工作流 + 指向式索引（31KB） |

### 2. 单一权威来源（Single Source of Truth）

同一知识**只在一个文件里维护**，其他位置用引用。

| 知识 | 权威位置 |
|---|---|
| 流程与约束 | 规格主控（`02-服化道/00-主控智能体.md`） |
| 落地方法 | 各模块 `引擎/`、`模板/` |
| 原始素材 | 各模块 `源skill库/`、`_规格原文/`（**仅追溯用**） |

**冲突裁决顺序**：规格 > 引擎/模板 > 源素材

### 3. 分层存放，不混淆用途

| 层 | 目录 | 是否参与日常使用 |
|---|---|---|
| 权威规格 | 各模块 `00-主控智能体.md` | ✅ 部署用 |
| 落地文档 | 各模块 `引擎/`、`模板/` | ✅ 查阅用 |
| 示例 | `示例演示/`、各模块 `示例演示/` | ✅ 参照用 |
| **原始素材** | `源skill库/`、`_规格原文/` | ❌ **仅追溯** |

新增内容前先问：**这是新知识，还是已有知识的重复？**

### 4. 改权威层必须同步实体层（⭐ 最容易踩的坑）

权威内容分三层，**只改上面两层会让改动"没生效"**——因为用户实操时复制的是第 ③ 层：

| 层 | 内容 | 改动后必须同步 |
|---|---|---|
| ① 事实来源层 | 规格原文 · 各模块 `00-主控智能体.md` | — |
| ② 规则/引擎层 | `引擎/*.md` · 模块 `README.md` | 指向 ① 的引用 |
| ③ **实体层** | `模板/*` · 可部署的合并版/总集 · `项目骨架/` 下 `_README` | ⚠️ **逐个同步** |

**真实案例**：把 06 合规主控从「八类/六法」升级为「十类/八法」并加了未决项联动，README 与引擎文件都改了——**但漏了同名模板**。用户按模板做合规检查时拿到的仍是旧口径。同类问题一次查出 **8 处**。

> **检查口径**：改完后用「关键字段 grep」验证——新机制的关键词能否在**模板**里搜到？命中 0 即为漏同步。

### 5. 改完跑一次自检

```bash
python 工具/校验.py
```

自动检出 12 类问题：引用断链（含**旧模块编号残留**）· 机制未覆盖到模板 · 废弃 ID 前缀残留 · 旧口径词残留 · 交付包字段缺失 · 素材被误删 · **文本被字符级替换损坏** · **数字声明过时** · **目录树与实际不符** · **模块编号/章节引用失效** · **共享表头不一致** · **档位声明与自身章节不符**。

详见 `工具/README.md`。

> **三种"看起来对"的陷阱**，本项目都踩过：
> ① 通读文档觉得结构完备 → 实际跑一个示例才发现机制缺口
> ② 打开主控觉得改完了 → 实际模板没同步
> ③ 替换成功没报错 → 实际文件已被静默损坏

### 6. ⚠️ 不要用 PowerShell / sed 做中文内容的批量替换

**真实事故（2026-09-23）**：用 PowerShell 批量替换中文片段时，`@(@("a","b"))` 这类**单元素数组会被展开**，`foreach` 拿到的是字符串而非数组，`$pair[0]` 取到**首字符**——于是 `.Replace()` 退化成**字符级替换**：

| 本意 | 实际执行 | 后果 |
|---|---|---|
| 替换「视觉分镜引擎.md …」 | `Replace('视','觉')` | 全文所有「视」→「觉」 |
| 替换「676 行 / 27.4 KB」 | `Replace('6','7')` → `Replace('7','3')` | 全文所有 `6`/`7` → `3` |

**3 个文件被静默损坏，而当时 6 类检查全部通过。**

**正确做法**：
- 改文件用**编辑工具**（走 Python），不要用 shell 拼 `.Replace()`
- 若确需脚本批量改，先把「旧值/新值」写成**成对列表并断言替换次数**，不要盲替换
- 替换后**立刻**跑 `python 工具/校验.py`（检查 7 就是为此加的）
