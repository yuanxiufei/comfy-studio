## 二、快速部署

### 方式一：直接部署（推荐）

把 **`00-主控智能体.md`** 全文粘贴到：

- ChatGPT → 创建 GPT → Instructions

- Claude → Project Instructions

若平台支持多文件挂载（RAG / 知识库 / 多工具 Agent）：


## 三、规格核心机制速览

### 5 条最高优先级规则（§00）

| 规则 | 内容 |
|---|---|
| RULE-001 | **图像优先**：先出图，再出 Prompt，再解释 |
| RULE-002 | **视觉一致性优先**：同角色核心视觉身份不得随机变化 |
| RULE-003 | **模块独立生成**：Character / Costume / Props 必须是三类独立资产 |
| RULE-004 | **统一世界观**：时代/地域/材料/色彩/光影全片统一 |
| RULE-005 | **默认禁止图像文字**：字母/数字/Logo/水印一律禁止 |

### 10 个意图路由（§02）

`INTENT-A CHARACTER` · `B COSTUME` · `C PROP` · `D ENVIRONMENT` · `E EXPRESSION`
`F POSE` · `G STORYBOARD` · `H FULL PROJECT` · `I MODIFY` · `J CONSISTENCY`

### 13 个锁定项（§14）

`LOCK_WORLD / CHARACTER / FACE / HAIR / BODY / COSTUME / PROP / ENVIRONMENT / COLOR / LIGHTING / CAMERA / EXPRESSION / POSE`

### 生产总循环（§41）

```
INPUT → INTENT ROUTER → PROJECT STATE → WORLD CONTEXT → ASSET CONTEXT
→ LOCK CHECK → REFERENCE CHECK → PROMPT ENGINE → QUALITY PREFLIGHT
→ IMAGE GENERATION → POSTFLIGHT → CONSISTENCY CHECK → ASSET UPDATE → USER OUTPUT
```

### 默认出图标准（§51）

Character / Costume / Props 一律：
**16:9 · 纯白背景 · 左侧细节 · 右侧三视图 · 柔和均匀光 · 无阴影 · 电影级灯光 · 写实拟真人 · 超高细节 · 8K · 无文字/Logo/水印**

Environment 例外：**非白色场景背景 · 电影级构图 · 多角度空间逻辑 · 与世界观统一**

## 四、与工作流其他模块的衔接

```
【01 剧本文本】小说/剧本
        ↓
【02 服化道】← 本模块（V2.0 规格）
   产出：VISUAL_BIBLE + CHARACTER DNA + 三视图 + 服装库 + 道具库 + 场景库 + 分镜基础
        ↓
【03 分镜导演】导演定调 + 节奏 + 分镜表 + AI 提示词
        ↓
【04 视频生成】分镜转视频（尾帧连贯 + 转场）
```

**分工边界：**
- 本模块负责 **资产本身**（这个世界长什么样）
- `03-分镜导演` 负责 **叙事调度**（怎么拍、什么节奏）
- `01-剧本文本` 负责 **人物与剧情**（谁、为什么、发生什么）

### ⚠️ 上游 `01-剧本文本/01-工业化编剧引擎.md` 会向本模块提三类要求

| 它产出 | 本模块接 | 落点 |
|---|---|---|
| 角色固定资产（外貌/发型/服装/配色/道具） | 建资产卡 | `模板/ASSET_CARD.yaml`（⚠️ **不用它自带的模板**） |
| 时代风格 / 画风默认 | 风格锁定 | `模板/VISUAL_BIBLE.md` ｜ ⚠️ **以本模块风格锁定表为准**（其"国漫二次元"仅作它独立运行时的默认） |
| 场景记忆点（色彩/建筑/材质/标志物/声音） | 建场景资产 | `项目骨架/…/05_ENVIRONMENTS/` |

> 另：其角色 ID 用 `CHR_XXX`、场景 ID 用 `ENV_XXX`（已按本项目规范对齐，非原文的 `P001`）。

### 本模块内部的「决策层 / 执行层」分工

| 文件 | 层级 | 负责 | 何时用 |
|---|---|---|---|
| `00-主控智能体.md` | **决策层** | 世界观 → 角色设计 → 服装/道具/场景 → 风格锁定 → 资产入库（六步 + 三闸门） | 要**规划整片美术**、定风格、建资产库 |
| `01-资产库出图引擎.md` | **执行层** | 一句话描述 → **自动补全 11 维度** → 出三视图资产图 → 输出完整 Prompt | 要**快速出一张资产图** |
| `引擎/TURNAROUND-STANDARD.md` | 规则层 | 四类资产的出图硬标准 + 可拼接英文段 | 查规范/负面词/变体版式 |

```
「这个世界长什么样、要设计哪些角色、风格怎么锁」   → 00 主控
「这个名字的角色，出一张三视图设定图给我」         → 01 出图引擎
```

**两者的版式差异**：
- `01-资产库出图引擎` 固定 **16:9 左特写 + 右三视图**
- `引擎/TURNAROUND-STANDARD.md` 另提供 **21:9（信息量优先）** 与三种三视图模板变体

### 01 出图引擎的核心机制

| 机制 | 说明 |
|---|---|
| **11 维度自动补全** | 年龄 · 性别表现 · 身材 · 面部 · 发型 · 气质 · 服装（四件套）· 材质（4 套世界观库 + 库外扩展规则）· 配色（五色）· 装备 · 特殊身体特征 |
| **补全粒度下限** | 各维度最少给几项（面部 ≥6、配色 5 色齐全、服装 4 件套齐全…）｜判据：**不看原输入也能画出同一角色** |
| **三视图一致性**（第一优先级） | 正/侧/背必须是同一角色；固定英文标准段声明 `same character, same identity, same face, same hairstyle, same body proportions, same costume, same accessories, same colors, same materials, same equipment across all views` |
| **10 项漂移禁止** | 装备背面消失 · 侧面换衣 · 背面发型变 · 正背配色不同 · 腿部比例变 · 武器数量变 · 护甲结构变 · 义肢消失 · 尾巴变化 · 翅膀数量变 |
| **资产卡优先**（防二次崩坏） | 项目已有 `ASSET_CARD.fixed_features` 时**只转译不重新补全**——否则同一角色会被补成另一套脸和服装 |
| **材质库扩展规则** | 库外世界观三段式：优先用已有 `material_bible` → 按最接近档扩展 → 并入该档（附民国/古装/蒸汽朋克/未来军事 4 个扩展示例） |
| **补全结果回写** | 出图后写回 `ASSET_CARD` / `VISUAL_BIBLE.color_bible` / `material_bible`；**不自行写入 ID 字段** |
| 固定版式 | 16:9 ｜ 左侧人脸/材质特写 + 右侧正·侧·背全身 ｜ 纯白背景 ｜ 棚拍光 ｜ 8K |
| **题材范例库** | **15 个题材的完整角色提示词**（可直接复制改用）+ 6 段句式公式（§三·3.5） |
| 输出规则 | **不解释/不总结/不描述图片**，直接输出完整可复用 Prompt（不用「同上」「见前文」） |
| 50+ 项 Negative | 见引擎 §五·5.4 |

### 引擎/ 的素材补强（来源：用户 `data/资料/` 素材）

| 引擎文件 | 补强内容 | 来源 |
|---|---|---|
| `引擎/EXPRESSION-POSE-LIBRARY.md` | **16 基线式 + 扩展 50 式**（按 8 族分组，含精准描述公式）；表情集网格扩展到 25/50 格 | `50种人物面部表情AI提示词.xlsx` |
| `01-资产库出图引擎.md` §三·3.5 | **题材范例库**：15 个题材的完整提示词 + 6 段句式公式 | `15种AI漫剧题材的人物提示词案例.xlsx` |

> 后 4 项（资产卡优先 / 材质库扩展 / 粒度下限 / 结果回写）是**实跑验证后补入**的——见 `示例演示/05-资产库出图实跑验证.md`。

**与主控的四项共用约定：** 一致性约束对齐**角色一致性 Gate** · 五色体系写入 `VISUAL_BIBLE.color_bible` · 材质与 `material_bible` 同源 · **出图不分配 ID**（正式 `CHR_`/`PRP_` 由 `01-剧本文本` 分配并在 `ID-REGISTRY.md` 登记）。

### ⚠️ 跨模块 ID 规则（本模块最关键的外部约束）

**所有 ID 从 `00_PROJECT/ID-REGISTRY.md` 读取，不得自造。**

| 段 | 谁分配 | 本模块能否新建 |
|---|---|---|
| `CHR_` / `CST_` / `PRP_` / `ENV_` | 01 剧本文本 | ❌ 不行（角色只能由 05 定） |
| **`POS_`**（姿态） | **本模块** | ✅ 可以 |
| `SHT_` | 03 分镜导演 | ❌ 不行 |
| `AUD_` | 05 音乐音频 | ❌ 不行 |

**状态机（`ASSET_CARD.yaml` 的 `id_status` 字段）：**

```
RESERVED  →  DRAFT  →  LOCKED  →  （DEPRECATED）
05 留号     本卡已建    已过 Gate     废弃
不可出图    不可投产    可全链路引用   号位保留不复用
```

**三条铁律：**
1. **升 `LOCKED` 只能由本模块执行**——因为只有本模块跑一致性 Gate。下游 03/04/04 不得自行升状态。
2. **号位永不复用**——废弃 ID 保留空位，防旧稿引用错位。
3. **不得自造未登记 ID**——发现剧本缺 ID 时（如某镜需要未列出的道具）→ 回报 05 补 `PRP_00X`。

**未决项联动**：涉及版权/授权的外部依赖问题（如风格参考图来源），须回查 `00_PROJECT/OPEN-ISSUES.md` 并追加登记，**不得自行判定"应该可以用"**。

> 规范权威：`00-总控路由.md` §四 ｜ 实例登记：`01-剧本文本/模板/ID-REGISTRY.md`
> 本 README 与 `引擎/LOCK-SYSTEM.md` 为规格（hash 锁定，不可改）的**规则补充层**。
