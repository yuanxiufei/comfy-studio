# Scene Multi-Angle Generator（场景多角度参考图生成器）

## 定位

**工具型子 skill，可在任意 skill 的场景生成或分镜生成阶段调用。**

- `historical-story-director` 到场景设定阶段 → 调用本 skill
- `romance-story-creator` 到分镜生成阶段 → 调用本 skill
- 其他任何需要场景一致性的 skill → 调用本 skill

**核心产物是「场景资产库」（内部使用，不展示给用户）**，包含：

1. S01 基准建立镜（大远景，纯文字 prompt 生成）
2. S02–S06 其余角度（以 S01 图片为 reference_image 生成，保证视觉一致性）
3. 资产索引表（供下游分镜生成时按景别/方向查表选图）

---

## 调用协议

### 调用方传入什么

```
【调用输入】
- 场景描述: [来自用户或剧本的场景文字描述]
- 视觉风格: [写实摄影 / 国画 / 动漫 / etc]
- 时代背景: [朝代 / 地域 / 现代 / etc]（可选）
- 时间段:   [清晨 / 午后 / 黄昏 / 夜晚]（可选）
```

### 本 skill 返回什么（**内部使用，全部不展示给用户**）

```
【调用输出 - 内部】
- 场景资产索引表（含编号、景别标签、方向标签、覆盖区域、图片URL）
- 固定描述块（供调用方在分镜 prompt 中复用）
```

### 对用户展示什么

**只展示一句进度提示**，不展示索引表、俯视图、prompt、或任何中间图片：

```
✅ 场景「[场景名]」资产库已建立，包含 [N] 个角度参考图，可用于分镜生成。
```

### 调用方怎么用这份输出

进入分镜生成阶段时，每条分镜执行以下查表流程：

```
分镜描述 + 景别
      ↓
查「场景资产索引表」（内部）
      ↓
匹配编号 → 取对应图片 URL
      ↓
将该 URL 作为 reference_image 输入 image_generate
      ↓
生成当前分镜图（展示给用户）
```

## 内部流程（用户不可见）

```
接收场景描述
      ↓
① [内部] 建立固定坐标系
      ↓
② [内部] 构建场景圣经（锁定所有物品位置/朝向/材质词）
      ↓
③ 向用户/调用方确认缺失细节（≤3个问题）
      ↓
④ [内部] 生成 S01 大远景（纯文字 prompt）
      ↓
⑤ [内部] 以 S01 图片为 reference_image，依次生成 S02–S06
      ↓
⑥ [内部] 一致性自审（坐标/家具/物品/光线）
      ↓
⑦ 向用户输出一行确认：「✅ 场景「[场景名]」资产库已建立」
```

## ① 固定坐标系

**用绝对方位，禁用"左/右"描述位置：**

```
  N（主采光面/主窗）
  ↑
W ←·→ E
  ↓
  S（入口/门）
```

- 所有物品描述使用 N/S/E/W 绝对方位
- 提示词中**禁止单独使用 left/right**（必须加方位前缀：`on the north wall` / `facing east`）
- 坐标系建立后全程不变，镜头切换不影响物品的绝对位置

---

## ② 场景圣经模板（内部使用）

```
■ 场景名称 / 空间类型 / 尺感 / 时代 / 时间段
■ 光源: 类型 | 方向(N/S/E/W) | 光色 | 投影朝向
■ 建筑结构: 门(位置/样式) | 窗(位置/数量/样式) | 地面 | 各墙面 | 顶面
■ 家具: 名称 | 位置(绝对方位) | 朝向 | 材质 | 与其他家具关系
■ 桌面/台面陈设: 物品 | 所在家具哪个位置 | 数量 | 材质词(锁定) | 朝向
■ 地面物品 / 悬挂物（如有）
■ 氛围 / 视觉风格
```

**关键规则：**

- **材质词、颜色词一旦写定，全程使用同一个词，禁止同义词替换**
- 不增加原始描述中没有提到的细节

## ④ 两阶段生图流程（核心一致性机制）

### 第一阶段：生成 S01 基准建立镜

- 纯文字 prompt（不需要参考图）
- `purpose: scene` ｜ `aspect_ratio: 16:9`
- prompt 结构：`[景别术语], [摄像机方位+朝向], [完整场景圣经内容], [光线], [风格词]`

S01 生成完毕后，**将其图片 URL 保存为 `[场景名]_S01_url`**，后续所有镜头必须引用。

### 第二阶段：以 S01 为基准生成 S02–S06

- 支持参考图输入
- `reference_images: [[场景名]_S01_url]`（**每张都传入 S01**）
- prompt 结构：`[景别术语], [摄像机方位+朝向], [该视角可见的场景圣经子集], [光线], [风格词], same scene as reference`

**为什么必须以 S01 为基准：**

- 每张图独立从文字生成时，模型对"相同场景"的理解各不相同，家具位置/光线/材质都会漂移
- 将 S01 作为参考图后，S02–S06 在视觉上锚定同一个空间，家具布局、光线色调、材质质感保持一致

## ⑥ 分镜选图规则（供调用方使用）

| 分镜景别 | 优先匹配索引编号 | 备选 |
|---|---|---|
| 大远景/建立镜/全景 | S01 | S05 |
| 远景（人物+环境） | S01 或 S02 | — |
| 中景（主要动作区） | S02 | — |
| 中景（书架/存储区） | S04 | — |
| 近景/特写（道具/手部） | S03 | — |
| 俯视/鸟瞰 | S03（俯角扩展） | S01 |
| 仰视/建筑感 | S06 | — |
| 借景/窗门框取景 | S05 | — |

**当分镜动作区域与标准角度不完全匹配时：** 选覆盖该动作区域的最近景别参考图，不必强求完全一致。

## ⑦ 标准角度组合

| 编号 | 景别 | 英文术语 | 用途 |
|---|---|---|---|
| S01 | 大远景 | extreme wide shot / establishing shot | 全局空间、光线氛围（基准图） |
| S02 | 中景 | medium shot | 核心活动区、家具+道具关系 |
| S03 | 特写/俯视 | close-up / overhead | 道具细节、台面质感 |
| S04 | 侧面纵深 | side angle with depth | 展示纵深层次 |
| S05 | 借景 | through doorway / window frame | 内外关系 |
| S06 | 仰视 | low angle | 建筑结构、顶部装饰 |

---

## ⑧ 每个镜头的 Prompt 结构

```
[景别术语], [摄像机方位+朝向], [可见建筑结构(固定块)], [可见家具陈设(固定块,含朝向)],
[可见台面/地面物品(固定块)], [光线(固定块)], [氛围/风格词]
```

S02–S06 额外追加：`, same scene as reference, consistent furniture layout and lighting`

**固定块规则：**

- 从场景圣经复制，**不改写，不替换同义词**
- 只写该视角**实际可见**的物品，不可见的不写
- 材质词/颜色词全程唯一

## ⑩ 一致性自审（内部）

```
坐标系: 窗/门位置是否一致？光源投影方向是否与坐标匹配？
家具:   位置/朝向/相对关系是否与俯视图一致？
物品:   数量/朝向/材质词是否完全一致？是否加入了原始没有的物品？
光线:   摄像机方位与光源方向是否逻辑自洽？
S01基准: S02–S06 是否全部传入了 S01_url 作为 reference_image？
```

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 直接生成分镜，没有先建场景资产库 | 场景资产库是分镜一致性的前提，**必须先生成** |
| S02–S06 独立从文字生成，未引用 S01 | 必须以 S01 为 reference_image，所有角度锚定同一基准图 |
| 将资产索引表、俯视图展示给用户 | 全部内部使用，对用户只输出一行确认 |
| 分镜生成时每次重新描述场景 | 用索引表取对应参考图 + 固定描述块复用 |
| 用"左/右"描述物品位置 | 用 N/S/E/W 绝对坐标 |
| 资产索引中不打景别/方向标签 | 标签是下游查表的唯一依据 |
| 物品材质词每次不同（壶/罐/器皿） | 场景圣经锁定后全程唯一 |

## 与本项目 V2.0 规格的映射

**这是「§32 场景连续性」的完整实现方法。**

| 本文机制 | V2.0 规格对应 |
|---|---|
| 固定坐标系 N/S/E/W | §32「主空间关系」的量化方法 |
| 场景圣经 | §32 锁定的「建筑/门窗/家具/地面/光源/主空间关系」 |
| 材质词全程唯一 | §04.3 Material Bible 的落地纪律 |
| S01 基准 + 引用生成 | **§16 资产继承规则**的图片级实现 |
| 资产索引表 | ENVIRONMENT INDEX 的扩充（增加方向/景别标签与图片 URL） |
| 分镜选图规则 | §12 SHOT ENGINE 与 ENV 资产的对接方式 |
| 固定描述块 | 风格锚点的场景级版本 |
| 一致性自审 5 项 | §18 CONSISTENCY ENGINE 的场景专项 |

### 建议的落地动作

1. **扩充 ENVIRONMENT INDEX**：增加「方向标签」「景别标签」「参考图 URL」三列
2. **在 §32 的锁定项中补充**：建立 N/S/E/W 坐标系并写入 VISUAL_BIBLE
3. **生图流程固化**：每个场景必须先出 S01 再出其余角度，禁止各角度独立生成
4. **在 04-视频生成 中复用**：尾帧链 + 场景资产库双锚定，多镜一致性更强
