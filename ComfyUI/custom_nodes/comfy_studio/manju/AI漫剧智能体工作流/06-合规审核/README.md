## 核心原则

> **不是删减创作，而是替换表述。能通过换词解决的问题，不改创意。**

### 过审优化八法

| # | 手法 | 做法 | 示例 |
|---|---|---|---|
| ① | 抽象化 | 具体 → 概念 | 血 → 暗色痕迹 |
| ② | 侧写化 | 直接 → 间接 | 打人 → 手停在半空 |
| ③ | 转移焦点 | 主体 → 反应/环境 | 尸体 → 法医动作 |
| ④ | 术语化 | 口语 → 专业中性词 | 杀人现场 → 案发现场 |
| ⑤ | 状态化 | 进行中 → 已完成 | 捅刺 → 凶器落地 |
| ⑥ | 删减 | 删除最激进元素 | 去掉伤情描写 |
| ⑦ | **正向化改写** | 消极设定整体转正向 | 末日废土互相残杀 → 未来生态重建团结协作 |
| ⑧ | **完全架空** | 创造全新虚构世界观 | 涉现实政治历史 → 全新架空设定 |

> ⑦⑧ 处理**反乌托邦/极端生存**与**时政/历史/民族敏感**最有效。

### 优化红线

- 不改变创作意图（只改表述不改情节）
- 不破坏视觉逻辑（优化后仍可生成）
- 不产生歧义
- 不过度保守（能保留的一律保留）

## ⭐ 未决项联动（防"假通过"）

发布前检查的第 10 项（音乐/音效版权）**不由本模块自行判定**，而是回查启动阶段建立的未决项表：

```
查 00_PROJECT/OPEN-ISSUES.md
→ 所有「版权授权」类的 BLOCKING / MAJOR 项是否均为 CLOSED？
   是 → 第 10 项 ✅
   否 → 第 10 项 ❌，整体判定降为「修改后可发布」
```

| 要求 | 说明 |
|---|---|
| **存在未关闭的 `BLOCKING` 项 → 不得判定"可发布"** | 硬规则 |
| **措辞用"核查登记项"而非"首次发现"** | 前者潜台词是"启动已知、生产未受阻、仅待用户决策"；后者意味着"现在才发现，可能已白做" |
| **不得自行判定版权可商用** | 版权类未决项必须用户确认 |

**与生产的关系**：`BLOCKING` 项未关闭时，✅ 允许继续分镜/资产/视频生成，❌ 不允许通过发布前检查——让**生产与法务并行**，而非串行等待。

详见 `01-剧本文本/模板/OPEN-ISSUES.md`。

## 免责提醒

⚠️ IP 评估基于通用特征比对，**不构成法律意见**。涉及具体作品比对时，应提示用户自行核查或咨询专业法律意见。
⚠️ AI 生成音乐的商用授权条款需用户自行确认——该问题应在**项目启动阶段**即登记为未决项，而非成片后才发现。
