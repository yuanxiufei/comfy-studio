> **本表是全项目 ID 的实例登记表。** 05 建纲时创建，02/03/04/05/06 全程读写。
> 落盘位置：`AI_DRAMA_PROJECT/00_PROJECT/ID-REGISTRY.md`

> ⚠️ **命名规范以 `00-总控路由.md` §四「跨模块资产 ID 交接协议」为唯一权威**。本文件不重新定义前缀，只负责**实例分配与状态跟踪**。两处若冲突，以总控为准。

## 一、为什么必须建纲时就登记（核心动机）

**问题**：EP01 只用到 `CHR_001/002`，但 `CHR_003`（反派）到 EP03 才出现。
如果等到 EP03 才分配 ID，会出现三种混乱：

1. **号段冲突**——EP03 想用 `CHR_003`，但 02 已在资产卡里把 `CHR_003` 用作某个路人
2. **引用断裂**——大纲里写"反派"，资产里叫 `CHR_003`，分镜里也叫 `CHR_003`，但没人在建纲时确认过它们指同一个
3. **后补成本**——EP03 补角色时，02 要重跑一致性 Gate，01 要回改分镜表

**规则：ID 在「全剧」层面一次性分配，不在「本集」层面增量分配。**

## 二、ID 段清单（前缀沿用总控 §四）

### 独立占号段（每个 ID 占一个号位）

| 段 | 前缀 | 格式 | 诞生模块 | 说明 |
|---|---|---|---|---|
| 角色 | `CHR_` | `CHR_<3位>` | 05 | 全剧统一，跨集复用同一 ID；状态后缀见下 |
| 服装 | `CST_` | `CST_<3位>` | 05 提逻辑 → 02 定稿 | 一套服装一个 ID，换装新建 |
| 道具 | `PRP_` | `PRP_<3位>` | 05 | 有叙事功能的道具才独立编号 |
| 场景 | `ENV_` | `ENV_<3位>` | 05 | 空间单位；同一空间不同天气仍为一个 ID，用状态后缀区分 |
| 动作 | `POS_` | `POS_<3位>_<动作名>` | 02 | 姿态库，跨角色复用 |
| 分镜 | `SHT_` | `SHT_S<场>_<3位>` | 01 | **按场编号**（总控格式），非按集 |
| 音频 | `AUD_` | `AUD_<类型>_<3位>` | 04 | 类型如 `BGM` / `SFX` / `VO` |

### 派生 ID（不占号位，由主 ID 推导）

| 类型 | 格式 | 例 | 由谁生成 |
|---|---|---|---|
| 状态变体 | `<主ID>_State_X` / `_<状态>` | `CHR_001_State_B`、`CST_001_Wet` | 02 |
| 表情 | `EXP_<CHR号>_<表情名>` | `EXP_CHR001_愤怒` | 02 |
| 镜头视频 | `VID_<SHT号>` | `VID_SHT_S01_006` | 03 |
| 版本 | `<主ID>_v<n>` | `CHR_001_v2` | 02 |

> 派生 ID 由主 ID 推导，**不需要在注册表占号位**，只需主 ID 存在且状态 ≥ DRAFT。

## 三、状态机

```
RESERVED  →  DRAFT  →  LOCKED  →  （DEPRECATED）
 已留号      已建资产     已过 Gate      废弃
 未出生      未过 Gate    可被下游引用    号位永久保留
```

| 状态 | 含义 | 下游可否引用 |
|---|---|---|
| `RESERVED` | 建纲时预留，尚未生成资产 | ⚠️ 仅可引用，不可出图 |
| `DRAFT` | 资产已建，未过一致性 Gate | ⚠️ 可用于内部预览，不可投产 |
| `LOCKED` | 已过 Gate，全链路可用 | ✅ 可投产 |
| `DEPRECATED` | 已废弃 | ❌ 不得引用 |

### 两条铁律

1. **号位永不复用**——`CHR_003` 废弃后，下一个角色用 `CHR_004`。理由：旧稿/旧提示词可能仍引用 `CHR_003`，复用会导致指向错误。
2. **升 `LOCKED` 只能由 02 执行**——因为只有 02 跑一致性 Gate。03/04/04 不得自行升状态。

## 五、各模块的职责边界

| 模块 | 对注册表做什么 | 禁止 |
|---|---|---|
| **01 剧本文本** | **创建**注册表，分配 CHR/CST/PRP/ENV 段（含预留） | 不分配 SHT_（属 01）、AUD_（属 04） |
| **02 服化道** | 补 CST/PRP/ENV 实资产 + 分配 POS_ 段，跑 Gate 后升状态 | 不得新建 CHR_（角色只能由 05 定） |
| **03 分镜导演** | 登记 SHT_ 段 | 不得新建 CHR/CST/PRP/ENV/POS |
| **04 视频生成** | 引用 ID + 生成 VID_ 派生 ID | 不得改任何 ID |
| **05 音乐音频** | 登记 AUD_ 段 | 不得改视觉类 ID |
| **06 合规审核** | 只读核查 | 不得修改（发现问题回报） |

**通用禁令**：任何模块**不得自造未登记 ID**。发现需要新 ID 时，回报 05 补登记。

## 六、建纲时的登记步骤（05 执行）

```
Step 1（创意定位后）→ 创建空表
Step 2（故事骨架后）→ 按三幕结构预判全剧出场角色，分配 CHR_ 号段
                      含"后续集才出现"的角色，一律 RESERVED
Step 3（角色设计时）→ 本集出场角色填全字段，其余保持 RESERVED
Step 4（分集大纲后）→ 按大纲回填 CST/PRP/ENV 段（含预留）
Step 6（交付包）    → 在交付包里附「ID 段分配情况」
```

### 交付包新增字段

```
ID 分配：
  本次启用：CHR_001, CHR_002, CST_001, PRP_001, ENV_001
  已预留未启用：CHR_003(EP03), CHR_004(EP05), CST_002(EP02), CST_003(EP02),
                PRP_002(EP02), ENV_002(EP02)
  注册表位置：00_PROJECT/ID-REGISTRY.md
```

## 七、冲突处理

| 冲突 | 处理 |
|---|---|
| 02 发现某 ENV 需拆分为两个空间 | **不新建 ID**，回报 05；确需拆分则 05 分配新号，原 ID 保持不动 |
| 分镜时发现某镜需要新道具 | 回报 05 补 `PRP_00X`，标 RESERVED → 02 建资产 → 可引用 |
| 某角色造型大改 | **不换 ID**，升版本号（`CHR_001_v1.1`），`CHANGELOG.yaml` 记录变更 |
| 某资产确定不用了 | 标 `DEPRECATED`，**号位保留不复用** |
| 发现总控 §四 未覆盖的新 ID 类型 | **先回报用户确认**，扩展总控 §四后再使用（不自行发明前缀） |

## 八、与总控「四张单子」的关系

`00-总控路由.md` §六要求跨模块始终一致的四项，本文件即其中的第一张：

| 单子 | 权威来源 | 本文件对应 |
|---|---|---|

| 变更记录 | `02-服化道/模板/CHANGELOG.yaml` | — |

**漂移检测**：每当有模块交付，检查其引用的 ID 是否都在本表中。有未登记 ID → 判定为漂移，打回补登记。
