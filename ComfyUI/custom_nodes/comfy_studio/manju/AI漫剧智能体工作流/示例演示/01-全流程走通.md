## 发现的两个改善点（✅ 已落地）

本次走通暴露的两个**跨模块机制缺口**，已实现为项目级共享文档：

### ✅ 缺口 1：ID 未预留 → 已建「跨模块 ID 注册表」

> **原文**：EP01 只用到 `CHR_001/002`，但 `CHR_003`（反派）到 EP03 才出现。应 05 建纲阶段就**预留完整 ID 段**并标注「待生成」。

**落地**：`01-剧本文本/模板/ID-REGISTRY.md`

| 机制 | 内容 |
|---|---|
| 分配粒度 | **全剧一次性分配**，不在本集增量分配 |
| 预留状态 | `RESERVED` → `DRAFT` → `LOCKED` → `DEPRECATED` 状态机 |
| 两条铁律 | ① 号位永不复用（防旧稿引用错位）② 升 `LOCKED` 只能由 02 执行（只有它跑 Gate） |
| 职责边界 | 05 定 CHR/CST/PRP/ENV；02 补资产 + 定 POS；01 定 SHT；04 定 AUD |
| 通用禁令 | **任何模块不得自造未登记 ID**，需要时回报 05 补登记 |
| 冲突解决 | 发现总控 §四 未覆盖的新 ID 类型 → **先回报用户确认**，不自行发明前缀 |

**命名规范统一**：本注册表**不重新定义前缀**，全部沿用 `00-总控路由.md` §四（`CHR_001` / `CST_001_Wet` / `SHT_S01_006` / `EXP_CHR001_愤怒` / `AUD_BGM_001`），本文件只管**实例分配与状态**。

### ✅ 缺口 2：版权项拖到 06 才发现 → 已建「未决项跟踪表」

> **原文**：AI 生成音乐的商用授权属于平台条款问题，非流程可控。应启动阶段（05）就列入「未决项」跟踪，而非拖到 06 才发现。

| 机制 | 内容 |
|---|---|

这个演示最大的产出不是"证明流程能跑"，而是**用真实链路暴露了结构缺陷**：

