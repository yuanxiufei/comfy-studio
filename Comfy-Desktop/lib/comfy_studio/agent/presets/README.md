# presets/ —— 随包附带的成品智能体

这里 6 份 `.md` 是**完整人设规格**，一份一个智能体。它们在面板的智能体下拉里直接可选；选中后
**整份正文原样**拼进系统提示词（底座规则之下那一段角色段，见 `agent/loop.py` 的
`compose_system_prompt`）。

## 与代码的关系

`agent/catalog.py` 的 `PRESET_AGENTS` 是这 6 份的清单：

| 清单里的 id | 下拉显示名 | 文件 | 正文体量 |
|---|---|---|---|
| `storyboard` | 分镜导演助手 | `分镜导演助手_完整迁移配置.md` | 42 KB |
| `script` | 剧本创作 | `AI剧本创作_完整迁移配置.md` | 49 KB |
| `costume` | 漫剧服化道 | `AI漫剧服化道智能体_完整迁移配置.md` | 31 KB |
| `asset` | 角色道具资产库 | `AI漫剧资产库角色道具_完整迁移配置.md` | 26 KB |
| `voice` | 调音大师班 | `调音大师班_完整迁移配置.md` | 35 KB |
| `lyrics` | 歌词创作 | `Suno歌词大师_完整迁移配置.md` | 43 KB |

清单提供 **id / 下拉显示名 / 一句说明**，这里的文件提供 **正文**。

为什么名字不直接从文件里读（用户放到 `--agents-dir` 的那些是直接从 `# 标题` 与 `>` 引用读的）：
这 6 份的标题带着「完整迁移配置」这类**用途**标记（见每份开头），直接拿来当下拉项又长又乱；
标题下面那段引用块时有时无（`AI剧本创作` 与 `AI漫剧资产库角色道具智能体` 两份就没有，紧跟
标题的是二级标题）。面板上显示成什么，与文档里写了什么，是两件事。

## 改这里要注意

- **正文一字不改地进系统提示词**：改文件就等于改这个智能体的行为，不必动代码。
- **增删/改名文件要同步 `PRESET_AGENTS`**：清单与目录对不上时会有一条测试失败
  （`tests/test_agents_tools.py` 的 `test_a_preset_that_is_missing_is_reported` 与
  `test_every_preset_file_is_listed`）。这不是形式主义 —— 清单里的文件名拼错时，那个智能体
  会从下拉里消失，只在 `problems` 里留一行，不跑测试很难发现。
- **正文会整份发给模型**：每份 2.6–4.9 万字符（约 2–3 万 token）。选中哪个才带哪个，但那一轮
  每一轮都带 —— 这是完整规格的代价，写在这里免得日后被当成"提示词怎么这么大"的 bug。
- **不要往这里放用户自己的智能体**。用户的文件放 `--agents-dir`（默认是工作台数据目录下的
  `agents/`）：那个目录每次开面板都现扫，用户随时能改；这里是随包内容，跟版本走。
  用户文件与这里 **id 相同**时以用户那份为准（他的文件覆盖随包预置，见 `catalog.py` 的
  `scan`）。

## 用途：整份带走

这 6 份文档**自包含**：不依赖本仓库的任何代码，复制到别的平台就能当 System Prompt /
Instructions 用。原先它们散在仓库根目录的「智能体搭建参考md/」里，现在收进此处 —— 内容一字
未动，只是换了住处，方便随包分发；那份目录说明里「对外迁移配置」的定位仍然成立。

每份开头都写明了用途，例如：

> 用途：将本智能体**迁移到其他 GPT / Agent / 工作流平台**时，作为完整的行为规范、
> 输出规范与提示词生成规范。
